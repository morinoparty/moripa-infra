## ネットワーク値

| 項目 | 値 | 備考 |
|---|---|---|
| ノードの OS | Ubuntu 26.04.1 LTS server | 全ノード共通 |
| 拠点構成 | site1 3台 / site2 2台、拠点ごとに独立クラスタ | site1 は 3台とも control-plane(etcd 3メンバー、schedulable、VIP でフェイルオーバー)。site2 は node1 = control-plane、node2 = worker(HA ではない) |
| ストレージ | Longhorn `1.12.1`(site1) | 既定 StorageClass `longhorn`、3レプリカ。ディスクは各ノードの `/data/longhorn`(ルート LV を VG 全体に広げた上のディレクトリ。OS 側の余裕は disk の storageReserved 30GiB)。UI は `longhorn.site1.private.dev.morino.party` |

| kube-vip VIP | site1 `10.200.1.10` / site2 `10.200.2.10` | cilium values の `k8sServiceHost` と一致。wg から届かないため管理者の kubectl は node1 の wg アドレス |

| kube-api ポート | `6443` | |

## HAProxy の TCP ルート(`ansible/group_vars/all/network.yml` の `tcp_routes`)

当面は空(Minecraft は最初の構築対象から外している)。行の形式は
`{ name, port, site, node_port, allowed_sources }` で、port を `site` の全ノードの
NodePort へ転送する。

L4 なのでクライアント実IPは届かない(Minecraft なら Velocity の modern
forwarding でプレイヤー IP を渡す)。`terraform` の `public_tcp_ports` =
`tcp_routes` の port + `proxy_public_ports` であること、`node_port` が
`kubernetes/sites/<site>/apps/<name>/service.yaml` の nodePort と一致することは
`make check-consistency` が検査する。

## wg 内の DNS(`ansible/group_vars/all/network.yml` の `wg_dns_*`)

ハブの dnsmasq(`roles/wg_dns`)が `10.100.0.1:53` で wg0 からの問い合わせにだけ
応答する。レコードは inventory と `wg_extra_peers` から生成される。

| 名前 | アドレス |
|---|---|
| `gw.wg.morino.party` / `linode-gw.wg.morino.party` | `10.100.0.1` |
| `<inventory_hostname>.wg.morino.party`(例: `site1-node1`) | そのホストの `wg_address` |
| `<wg_extra_peers[].name>.wg.morino.party`(例: `admin`) | その peer の `allowed_ips` |

ゾーン外の問い合わせは `wg_dns_upstreams`(1.1.1.1 / 1.0.0.1)へ転送する。
クラスタ用の `10.200.x.x` は wg から届かないため登録しない。クライアント側の
設定は `/docs/admin/keys` を参照。

## Caddy の公開ルート(`gateway/caddy/Caddyfile`)

ルーティング表は Ansible 変数ではなく git の `gateway/caddy/Caddyfile`。ハブの
`caddy-gitops.timer` が `main` を取り込み、`caddy validate` を通してから reload する。

| ホスト名 | 転送先 | 認証 |
|---|---|---|
| `*.site1.dev.morino.party` | site1 の全ノード `:80` | なし |
| `*.site2.dev.morino.party` | site2 の全ノード `:80` | なし |
| `*.site1.private.dev.morino.party` | site1 の全ノード `:80` | oauth2-proxy |
| `*.site2.private.dev.morino.party` | site2 の全ノード `:80` | oauth2-proxy |
| `auth.dev.morino.party` | oauth2-proxy(ログイン選択画面 + コールバック) | — |

証明書は Cloudflare DNS-01 のワイルドカード(階層ごとに 1 枚)。上記の各名前は
Cloudflare で `gateway_public_ip` に向ける(DNS only)。

| 変数(`network.yml`) | 値 | 備考 |
|---|---|---|
| `proxy_public_ports` | `[80, 443]` | Caddy が listen するポート |
| `caddy_gitops_repo_url` / `_branch` / `_subdir` / `_interval` | 本リポジトリ `main` の `gateway/caddy`、3 分 | ハブの取り込み設定 |
| `oauth2_proxy_enabled` | `false` | `true` にするまで `*.private.*` は 503(fail closed) |
| `auth_host` | `auth.dev.morino.party` | oauth2-proxy のコールバック先 |
| `auth_cookie_domain` | `.dev.morino.party` | セッション cookie の共有範囲 |
| `oauth2_proxy_providers.github` | port 4180、org `morinoparty` | GitHub org メンバーを許可 |
| `oauth2_proxy_providers.mineauth` | port 4181、`roles` に `staff` | MineAuth(OIDC)。`issuer_url` は要設定 |

秘密(Cloudflare トークン、client id/secret、cookie secret)は
`ansible/group_vars/gateway/auth.sops.yml`。設定手順は `/docs/admin/auth`。
