## ネットワーク値

| 項目 | 値 | 備考 |
|---|---|---|
| ノードの OS | Ubuntu 26.04.1 LTS server | 全ノード共通 |
| 拠点構成 | 2拠点 × 3台、拠点ごとに独立クラスタ | 各拠点3台全部 control-plane(stacked etcd・schedulable)、API VIP は kube-vip |
| site1 LAN CIDR | `192.168.10.0/24` | ノード `.11`–`.13`(**DHCP + ルーター側 MAC 予約で固定**)、kube-vip VIP `.10`(DHCP プール外) |
| site2 LAN CIDR | `192.168.20.0/24` | 同上 |
| ノードの LAN IP 管理 | DHCP 予約 | inventory には書かない。管理は wg アドレス、k8s は実行時ファクトで LAN IP を取得(`/docs/admin/ansible` の予約表参照) |
| WireGuard CIDR | `10.100.0.0/24` | site1 は `.11`–`.13`、site2 は `.21`–`.23`。LAN / Pod / Service と重複しないこと |
| WireGuard ポート | `51820` | ハブの ListenPort |
| WireGuard MTU | `1420` | 1500 − 80(オーバーヘッド + 余裕) |
| Pod CIDR | `10.244.0.0/16` | **両拠点で同一値**(`/docs/architecture/multi-site` 参照) |
| Service CIDR | `10.96.0.0/12` | 同上 |
| kube-api ポート | `6443` | |
| 外部公開ポート | Minecraft `25565`、HTTP/HTTPS `80`/`443` | Linode 側 DNAT(現状すべて site1 向け)。SSH は公開せず wg 経由のみ |
| 秘密情報の管理 | sops + age | Ansible vars と k8s Secret の両方で使用。cluster 鍵と deploy key は両拠点共有 |

## DNAT ルール(`ansible/group_vars/all/network.yml` の `dnat_rules`)

| name | proto | dport | target | tport | 備考 |
|---|---|---|---|---|---|
| minecraft | tcp | `25565` | `10.100.0.11` | `30565` | site1-node1 の NodePort(eTP Local) |
| http | tcp | `80` | `10.100.0.11` | `80` | site1 Cilium Gateway(hostNetwork) |
| https | tcp | `443` | `10.100.0.11` | `443` | 同上 |

`target` / `tport` の対応関係、および `terraform` の `public_tcp_ports`
との一致は `make check-consistency` が検査する。
